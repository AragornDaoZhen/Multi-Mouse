# Multi-Mouse — 多鼠标独立光标

让 Windows 同时使用多个物理鼠标，每个鼠标拥有独立的光标和点击。

## 快速开始

**有 Python 环境：**
```
python run.py
```
或双击 `启动多鼠标.bat`，关闭窗口即退出。

**无 Python 环境：**
使用 PyInstaller 打包：
```
pip install pyinstaller
pyinstaller --onefile --console run.py
```
生成的 `dist\run.exe` 可直接运行。

## 自定义光标图标

在项目根目录放置 PNG 图片（建议 32×32 左右，带透明背景）：

| 文件名 | 对应鼠标 |
|--------|----------|
| `cursor0.png` | 第一鼠标（主鼠标） |
| `cursor1.png` | 第二鼠标 |
| `cursor2.png` | 第三鼠标 |

没有自定义图片时，使用内置的三角形光标（主鼠标灰色，副鼠标蓝色）。

## 实现方式

### 架构

```
物理鼠标 → WH_MOUSE_LL 钩子拦截 → 原始输入 (WM_INPUT) → 合成事件 (SendInput) → 应用程序
```

1. **WH_MOUSE_LL 低级钩子** — 拦截所有物理鼠标事件，阻止它们到达应用程序
2. **Raw Input API (WM_INPUT)** — 接收每个鼠标的原始移动/点击数据，按设备句柄区分不同鼠标
3. **SendInput 合成事件** — 根据原始输入生成正确的光标移动和点击事件，发送给应用程序
4. **Layered Window 覆盖层** — 为每个鼠标渲染独立的光标图标（透明、置顶、点击穿透）

### 光标定位

- 原始输入提供相对位移（delta X/Y），累加得到每个鼠标的绝对坐标
- 主鼠标：系统光标通过 `SetCursorPos` 跟随
- 副鼠标：系统光标通过 `SendInput(ABSOLUTE|MOVE)` 跟随（触发悬停效果）
- 每个鼠标有独立的覆盖层光标（Layered Window），始终显示在正确位置
- 主鼠标覆盖层在移动时自动隐藏（避免与系统光标重叠），静止 250ms 后重新显示

### 点击处理

- 物理点击被 WH_MOUSE_LL 拦截丢弃
- 根据原始输入中的按钮标志，通过 `SendInput` 发送合成点击：
  - **按下**：`(移动到目标, 按钮按下)` — 2 事件原子批次
  - **释放**：`(移动到目标, 按钮释放, 恢复到主光标位置)` — 3 事件原子批次
- WH_MOUSE_LL 检查 `LLMHF_INJECTED` 标志，放行合成事件

### 拖拽

- 按住的鼠标可以正常拖拽（光标跟随移动）
- 未被按住的鼠标移动不会干扰拖拽

### 自定义光标加载

使用 Windows 内置 GDI+ 加载 PNG 图像，渲染到 32 位 BGRA 位图，通过 `UpdateLayeredWindow` 显示。

## 已知限制

1. **部分 UWP/管理员窗口可能无响应** — 非提权进程的 `SendInput` 受 UIPI 限制，无法向高完整性级别窗口注入输入。以管理员身份运行可缓解。

2. **无鼠标加速** — 原始输入提供的是设备原始数据，Windows 的指针加速/速度设置不生效。光标移动为 1:1 像素映射。

3. **最多支持鼠标数取决于 USB 端口** — 实际测试过 2-4 个鼠标，理论上更多。

4. **需要 Windows Vista 或更高版本** — WH_MOUSE_LL 和 Raw Input API 均为 Vista+ 特性。

5. **副鼠标拖拽时系统光标可能闪烁** — 拖拽期间系统光标跟随副鼠标移动，释放后回到主鼠标位置。

6. **DPI 缩放** — 在高 DPI 显示器上，覆盖层光标位置可能有微小偏差（未做 DPI 感知适配）。

7. **杀毒软件可能报警** — WH_MOUSE_LL 是全局钩子，某些安全软件可能将其标记为可疑行为。
